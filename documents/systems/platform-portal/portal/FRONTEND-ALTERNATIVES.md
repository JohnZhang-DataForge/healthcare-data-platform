# Public OpenLineage frontend alternatives — Agent D / 7.10

> **Research finding, not an approved architecture or deployed website.** 2026-10-27 ET (public-source audit; GitHub UTC activity may show Oct 28). This report is the only maintained 7.10 research deliverable. No third-party code was copied, built, or deployed; no private Marquez, Blob, Azure, Kubernetes, Spark or database was accessed. Source/license evidence was **read**, but clean npm builds, browser demos, vulnerability scans and live JSONL compatibility have **not** been executed. Workday estimates are planning ranges, **not measured timings**. Main Session owns the technology decision.

## Executive decision

**Primary recommendation: `@xyflow/react` (React Flow) + `dagre` for layout, consuming the existing `portal.snapshot.v1` graph, with Agent A's original GET-only adapter retained.** It is a **library-based static website**, not an already finished lineage website. It trades a *small, explicitly bounded amount of first-party UI work* for clear MIT redistribution rights, browser-only deployability, professional custom table/column cards, and no Marquez/API backend. **Estimated 2–4 focused engineer-days for an interview-ready minimum**, plus review/build/visual QA; not a guarantee. React Flow already provides zoom/pan/selection and controls. Dagre adds client-side directed layout. A data mapper and details/timeline shell are our code. Avoid Pro templates unless separately licensed.

**Fallback: Apache ECharts Graph**, Apache-2.0, as a smaller 1–2-day first-pass *table-only graph* plus 1–2 more days for legible field-level lineage. This is the **fastest legally publishable functional minimum** if recruiter-ready column cards are not a day-one blocker. It does **not** deliver a Marquito-like column UX automatically. If visual column lineage is a release-blocker and React Flow slips, review `react-lineage-map` in an isolated spike, but do **not** adopt that lightly: single-maintainer, last push 2025-04-13, no working test script, and no independently verified browser build.

**Do not fork Marquez Web, DataHub or OpenMetadata for the public site merely because they are mature.** Their licenses are valid, but their web application features assume metadata APIs and a server-side platform; porting their entire UI to a static JSON bundle is disproportionate to Emory recruiter needs. A mature backend does not imply a ready-to-host static front end.

**Shortest code path:** the already frozen `GET /data/latest.json` contains `runs[]`, `datasets[]`, `lineage.table_edges[]`, and `lineage.column_edges[]`. Draw the initial graph, per-run timeline and details from **these typed, pre-approved public refs**, not by reparsing complete OpenLineage. Keep `GET /data/lineage/latest.jsonl` as a proposed *optional* richer source until Coordinator accepts a JSONL pairing/integrity policy. This cuts the first browser PoC's dependence on the presently incompatible A/B JSONL contract.

### 3.1 Marquez Web UI — complete product, static-port rejection

- Source/site: [Marquez repository](https://github.com/MarquezProject/marquez), [Web source](https://github.com/MarquezProject/marquez/tree/main/web), [official README](https://github.com/MarquezProject/marquez/blob/main/README.md), [Web `package.json`](https://github.com/MarquezProject/marquez/blob/main/web/package.json), [OpenAPI](https://github.com/MarquezProject/marquez/blob/main/spec/openapi.yml), [releases](https://github.com/MarquezProject/marquez/releases).
- **License:** [Apache-2.0 LICENSE](https://github.com/MarquezProject/marquez/blob/180f37b22387146187af1ef0279e3ee1d1ccd789/LICENSE); Web's `package.json` also states Apache-2.0. Redistribution permitted under its obligations.
- **Observed activity:** repo last pushed **2026-10-26 UTC**, nonarchived; latest GitHub release from checked endpoint **0.50.0 (2024-10-24)**. This is *active source but an old tagged release*, not proof of current frontend dependency health. Web has Webpack, React/Redux/MUI, diverse deps; supply-chain audit required.
- **Behavior evidence:** official README says UI on `localhost:3000` with Marquez API at `localhost:5000`, displaying lineage and current/previous job runs; OpenAPI has `GET /column-lineage` and namespace-qualified Job/Dataset routes, plus namespace-filtered search.
