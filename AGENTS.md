# Healthcare Data Platform — Agent entry

**Mandatory for every agent/tool/session.** This file is a small safety and routing entrypoint, not an implementation diary. Inspect the **latest** Git main SHA and open PRs before changing anything. Never treat an unmerged PR, dated handoff, prior run, or plan as the current verified implementation.

## 1. Single source of task truth

- **Work in progress:** [active OpenSpec Changes](openspec/changes/) are the sole maintained source of each change's Proposal, Design, Specs, `tasks.md` OPEN/DONE and acceptance. Read **only the relevant Change**, not all old tasks. [OpenSpec lifecycle](documents/engineering/development/OPENSPEC-DEVELOPMENT-LIFECYCLE.md) and [configuration](openspec/config.yaml) govern process.
- **Adopted behavioral contracts:** [Current Specs](openspec/specs/). **Completed/retired work:** [Archived Changes](openspec/changes/archive/) and immutable Git PR/Run/SHA evidence. An archived Change is not a live task.
- **System ownership and implementation:** [documents/README.md](documents/README.md) → relevant `documents/systems/<system>/README.md` and `CODE.md` → actual canonical source/tests/contracts. Docs provide architecture/operations, not duplicated task progress.
- **Legacy compatibility link:** [PROJECT-STATUS.md](documents/engineering/status/PROJECT-STATUS.md) is now navigation-only; its historical snapshot is **not CURRENT**. Use the read-only dynamic CLI `python3 .github/quality/scripts/active_openspec_index.py` for a sorted, on-demand Active Change summary. The index is computed from the current checkout, not a second manually synced list.
- **Actual evidence:** source SHA + PR + GitHub Actions Run/Artifact + independent runtime readback appropriate to the claim. Distinguish PLAN, SOURCE, STATIC, RUNTIME and durable E2E. A static PASS is not Warehouse Gold COMMIT or Fabric deployment.

## 2. Non-negotiable safety and Git governance

1. Read [Agent Rules](documents/engineering/development/AGENT-RULES.md); for code changes read [Development Workflow](documents/engineering/development/DEVELOPMENT-WORKFLOW.md), [Component Naming](documents/engineering/development/CODE-ORGANIZATION-AND-NAMING.md) and relevant CODE owner. New code/test/workflow files use **component/function** names, not `taskNNN/stepNNN`. Preserve legacy names without unreviewed refactors.
2. Work in a bounded branch/PR from latest main. **Material code, Workflow, architecture, governance or CODE-map changes require an active OpenSpec Change beforehand.** Every relevant PR declares `OpenSpec-Change: <id>` and `OpenSpec-Task: <n.n>` on separate lines, and modifies that Change's `tasks.md`. Required GitHub [Trusted Change Gate](.github/workflows/openspec-trusted-change-gate.yml) and [OpenSpec validation](.github/workflows/openspec-validation.yml) must remain enforced. Never bypass Ruleset or edit protected checker/baseline in a normal PR.
3. New automated tests: `.github/quality/tests/<system>/<component>/`; new quality scripts: `.github/quality/scripts/`; test fixtures: `.github/quality/fixtures/`; human-readable component docs: `documents/`, not new source READMEs. Pre-existing exact-path legacy files are not permission to reintroduce deleted paths. [Current layout spec](openspec/specs/repository-quality-layout/spec.md). Update owning system/component `CODE.md` in the same PR when changing maintained source entrypoints.
4. **No shared-runtime operation from documentation alone.** Before any K8s/Airflow/Spark/PG/S3/Azure/Fabric/Marquez action, publishing, `terraform plan/apply/destroy`, retry, cleanup or reset, read [Safe Operations](documents/engineering/operations/SAFE-OPERATIONS.md) and [Session Coordination](documents/engineering/development/SESSION-COORDINATION.md), inspect active jobs/PRs and obtain authorization for the exact side effect. Unknown ownership, uncertain COMMIT, immutable batch or resource collision means **HOLD and read-only investigation first**. Never disclose credentials.
5. Prefer existing version-pinned Self-Runner workflows for authorized execution and record exact target SHA, Run, manifest/batch and independent readback. Do not blindly replay an old writer or claim cloud success from Git or CI alone.
